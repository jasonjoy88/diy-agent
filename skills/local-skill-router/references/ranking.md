# 从 codegraph 命中到调用链

图谱负责召回，本文件负责怎么问、怎么收成一条短链。打分脚本只消费图谱已经返回的候选，不扫描技能库目录。

## 查询

对技能库根目录调用宿主的 codegraph 工具（常见名 `codegraph_explore`）：

- `projectPath`：技能库根目录的绝对路径（其下或其上必须有 `.codegraph/`）
- `query`：`keywords` + `domain` + 形态触发词 + `SKILL`
- `maxFiles`：12

命中偏少时，用 `task_type` 里的词再查一次。两次之后仍没有 `SKILL.md`，就说明索引里没有对口技能，停止并告诉用户。不要改成全库文件名遍历。

从返回正文里只收 `SKILL.md`。若命中的是技能目录里的其它文件，只取该目录下的 `SKILL.md`，并只用图谱已经给出的正文；正文被截断时，只读这一份 `SKILL.md` 的开头来补名称和 description。

候选写成：

```json
[
  {
    "id": "与 frontmatter name 一致，缺省则用目录名",
    "name": "展示名",
    "description": "frontmatter description，截到约 700 字",
    "path": "SKILL.md 的绝对路径"
  }
]
```

排除本技能自己（`local-skill-router`）。

## 阶段

按描述把入选技能放进四段，顺序固定为 **调研 → 生产 → 加工 → 质检**：

| 阶段 | 描述里常见信号 |
|---|---|
| 调研 | 调研、研究、检索、竞品、资料 |
| 生产 | 撰写、生成、方案、脚本、实现 |
| 加工 | 排版、格式、导出、幻灯片、表格、成稿 |
| 质检 | 检查、校对、评审、质检、验收 |

同一阶段最多 2 个。整链默认不超过 6 个。质检段有命中时不要省。

## 呈现

只把最终调用链告诉用户：每一环一个技能名、阶段、一句话理由。不要把图谱命中全倒出来。分数只用于排序；描述读起来明显不对时，以阅读为准，收紧关键词再查一次图谱。
